## 3. Provenance & metadata
Every manifest row carries `source_dataset, source_id, source_url (where known), license, country + country_source, language + language_source, merchant (only where the source gives one), layout_id (only db_online_ticket is known; otherwise null), synthetic, collection, label_quality, label_source, batch, source_type, n_pages, hard_negative, group_id, split`. Unknown stays null. Languages not stated by the source were detected from OCR text with langdetect (prob >= 0.8; language_source = langdetect); 655 documents stay `unknown`.
581 real documents have unverified/unstated rights (user batches, hf medical bills, scraped financial images): see `license` per row.

## 5. Duplicates and leakage
* Exact duplicates dropped: 149 (SROIE re-scans, repeated files across the new batches); corrupt: 2. Near-duplicate pairs: 15,121 -> 440 multi-document groups, largest 162 (one DB ticket template). Rule: pHash <= 4 OR (pHash <= 6 AND dHash <= 8), plus same-merchant groups (SROIE company, ReceiptBench/PT seller, my_receipts filename prefix, DB-ticket layout).
* Cross-source overlaps found (kept in one split): in_financial+manual_in 3, receiptbench+user_real 4, receiptbench+sroie 2, my_receipts+receiptbench+sroie 1.
* Independent audit (`scripts/audit_leakage.py`, does not reuse the grouping rule): real val/test images with a TRAIN neighbour at pHash <= 4: **0 / 0** (the first version of the grouping left 10 val / 6 test; fixed). At <= 8 (similar template, not near-identical): 37 val / 26 test of ~550 each; this residual is accepted and documented.
* Augmentation is never materialised, so it cannot leak.

## 6. Sanity check after integration (not the project baseline)
TF-IDF + LogisticRegression on OCR text: val macro-F1 0.919, test 0.889; **real-only test** acc 0.812 / macro-F1 0.676 (n=361); synthetic-only test 1.000 (still meaningless). Weak real classes: medical (recall 0.17, n=6), gas (0.25, n=4), train (0.29, n=28: unseen layouts), internet (0.33, n=6), bus (P 0.45). Real test sets are 4-18 documents for most weak classes, so per-class numbers are noisy.

## 7. Is Task A ready?
**Yes for starting training, with caveats.** Every class except `rent` now has real documents; hotel, flight, bus, transport, electricity, internet, food, fuel, parking and train have 63-927 real documents from 27-591 independent groups. Remaining weaknesses:
1. `rent`: zero real documents (synthetic only).
2. Thin or low-diversity real data: gas (30 groups, 33 of 40 Indian), water (30 groups, ~38 near-identical Delhi Jal Board bills), medical (43 groups, only 15 genuine Indian, no license), internet (27 groups).
3. flight/transport/hotel/bus are mostly foreign; real Indian flight and hotel documents are still 0 (7 Indian bus, ~0 Indian transport). ReceiptBench has more Indian taxi/bus/flight/hotel receipts that were not in the capped subset: raise `CAPS` in `acquire_real_foreign.py` (cheap, ~19 images/minute).
4. Real val/test per weak class is 4-18 documents; use group cross-validation for model selection and report confidence intervals.
5. Rights: 581 real documents with unstated/unverified terms; keep the dataset internal.
6. Metro/tram tickets are labelled `transport` (local transit), not only cab/taxi.

## Addendum 2026-10-05: cab / taxi search
Searched Kaggle (ola/uber/rapido/cab/taxi/ride receipt|invoice|bill), Hugging Face and the web. Result: **no public dataset of cab/ride-hailing receipt images exists**; the Kaggle hits are tabular (NYC taxi trips, Rapido/Uber driver and ride data, a synthetic 50k-row Indian driver table) and bill-generator websites are synthetic.
