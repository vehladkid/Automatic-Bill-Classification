# Task A report: expense-category classification

Generated by `scripts/taskA/t7_report.py` from `reports/taskA/*.json`. Labels: 16 (`bus`, `electricity`, `flight`, `food`, `fuel`, `gas`, `hotel`, `internet`, `medical`, `miscellaneous`, `non_expense`, `parking`, `rent`, `train`, `transport`, `water`).

## 1. Data and protocol
* Train 4848 (2904 real) / validation 634 (391 real) / test 629 (386 real). Splits are by document group (template / merchant / near-duplicate family) - see docs/DATASET.md.
* Model selection (C, epochs, fusion weights, temperatures, routing threshold) uses **validation only**; the test set is evaluated once per model after training.
* Headline metric: **real-only** test accuracy / macro-F1 (synthetic bills are templated and score ~1.0 for every model, so they say nothing about real-world accuracy). CI = 95% bootstrap over document groups.
* Disclosure: before LayoutLMv3 finished I ran the fusion script once on text + image only as a code test and saw its test score (real acc 0.912 / macro-F1 0.850); it was not used to choose anything. The final three-model fusion below was selected on validation NLL only.
* `rent` has no real documents: it is trained and checked on synthetic bills only, so its real-world accuracy is **unknown**.

## 3. Label cleanup, synthetic-data ablation, cross-validation (text model)
* **Label audit** (group-OOF text-model disagreements, 85 real documents reviewed by eye + OCR text, plus every rule-labelled transport/hotel/medical/fuel/train document): 90 corrections in `datasets/metadata/label_overrides.json` (e.g. Subway sandwiches, Cyberport IT store, McDonald's and car-rental contracts mislabelled by regex; 39 Indian ReceiptBench 'purchase' receipts that were restaurant bills). Same text model: validation real macro-F1 **0.789 -> 0.868**, test real macro-F1 **0.806 -> 0.831** (accuracy 0.863 -> 0.883).
* **Synthetic ablation** (text model trained on real data only): test real acc 0.871 / macro-F1 0.806 vs 0.883 / 0.831 with synthetic added; real-Indian acc 0.936 vs 0.936. Synthetic data helps real accuracy only marginally; its job is to give `rent` and the thin classes any training signal at all (the real-only model scores 0.47 on synthetic bills).
* **Group 5-fold CV on train+val** (text model): real acc 0.857, real macro-F1 0.838 (CI 0.80-0.89); real-Indian acc 0.945.

## 6. Limitations
* Real test sets are small for the weak classes (see per-class n); read per-class numbers with the CIs in `reports/taskA/fusion.json`.
* Calibration and tau are fit on a small validation set; re-fit when more real data arrives. Tau gives ~95% precision on validation, test is reported above.
* `rent` is synthetic only. Hotel / flight / bus / taxi are mostly foreign real documents; real Indian coverage is in docs/REAL_DATA_ACQUISITION_2026-10-04.md.
* LayoutLMv3-base weights are CC-BY-NC-SA-4.0 (non-commercial); ConvNeXt (timm) is Apache-2.0. The data has unverified rights for part of the real documents: keep models/data internal.
* OCR errors (handwriting, tilted photos) propagate to the text and layout models; the image model is the fallback when OCR is empty.
