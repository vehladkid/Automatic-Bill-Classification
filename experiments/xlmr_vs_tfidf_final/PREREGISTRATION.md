# Pre-registration - XLM-RoBERTa vs TF-IDF + Logistic Regression (written BEFORE any new training or test-set evaluation)

Date written: 2026-10-28 (before launching `run_queue.sh`). The earlier single XLM-R run (`experiments/text_vs_neural/outputs/m5_xlmr.json`) has already been seen; it does not decide anything below.

## Questions
Q1 Is XLM-R demonstrably better than TF-IDF + LR at classifying expense documents (same documents, same labels, same splits)?
Q2 If it is better, does the gain justify its cost (latency, memory, size, training, deployment)?

## Fixed design (not to be changed after seeing test results)
* **Data/splits:** the project's Task A split files and `scripts/taskA/common_a.load` (train 4,848 / val 634 / test 629). Headline = REAL test documents (n = 386; macro averages over classes present in the real test set), identical to the earlier study. Input text = `row["text"]` (stored RapidOCR text), no extra normalisation.
* **Baseline:** the production TF-IDF (char_wb 2-5 + word 1-2, sublinear, C = 10, balanced) - re-fitted and checked against `models/taskA/text_lr.joblib`; not retuned.
* **Primary XLM-R configuration (the original protocol, replicated):** `FacebookAI/xlm-roberta-base`, max length 256 tokens INCLUDING the two special tokens, truncation keeps the start of the text, 6 epochs maximum, early-stopping patience 2, AdamW lr 3e-5, weight decay 0.01, 10% linear warm-up then linear decay, batch 16, bf16 autocast, grad-clip 1.0, class-balanced cross-entropy, the 250k-token word-embedding matrix FROZEN (86,054,416 trainable of 278,055,952 parameters). **Checkpoint selection = the epoch with the best VALIDATION real-only macro-F1.** Seeds 0-4 (five runs; five more seeds 5-9 only if time allows, decided by time, not by results).
* **Primary metric:** macro-F1 on the real test documents. Secondary: accuracy, macro precision/recall, weighted-F1, per-class F1, ECE/NLL/Brier (temperature fitted on validation only).
* **Primary statistic:** Delta = mean over seeds of [macro-F1(XLM-R seed s) - macro-F1(TF-IDF)] (point estimate, not a bootstrap mean). 95% interval = hierarchical percentile bootstrap, B = 10,000: each replicate resamples whole template/merchant groups of the test set with replacement AND draws five training seeds with replacement; both classifiers are scored on the same resampled documents. Also reported: per-seed paired-bootstrap intervals, a t-interval over the five seed-level differences (seed uncertainty only), exact McNemar tests per seed (they test paired CORRECTNESS, not macro-F1).
* **Decision rule (primary comparison only):**
  * A "superiority established": Delta > 0 AND the lower end of the 95% hierarchical interval > 0.
  * B "practically meaningful superiority established": the lower end of the interval > 0.02 (absolute macro-F1; provisional threshold).
  * C "inconclusive": otherwise.   D "inferior established": the upper end of the interval < 0.
  Observed-score statements ("XLM-R scored higher"), statistical superiority (A), practical superiority (B) and "better production trade-off" (a separate cost-benefit judgement) are reported as different claims.
* **Exploratory analyses (not used for the primary decision):** longer input (512 tokens), overlapping chunks with mean-logit aggregation, a longer-training variant (10 epochs), TF-IDF under the same truncation. Configuration choice among exploratory variants uses VALIDATION macro-F1 of seed 0 only. Any claim from an exploratory variant must survive a Bonferroni correction over the number of exploratory variants tested.
* **Never done:** tuning, checkpoint selection or early stopping on test data; changing the split; selecting seeds by test performance.

## Resource-cost protocol (decided now)
Same machine for all models, 4 CPU threads, warm-up 5, >=100 repetitions (>=15 for slow models), median and p95; model-only vs end-to-end (tokenise/vectorise included) reported separately; batch sizes 1/8/32 for throughput; peak CPU RSS measured per model in a fresh process; GPU peak via torch; training time = measured wall-clock for runs made here, historical values labelled as historical.

## Addendum (written after the five-seed primary result was known - macro-F1 difference +0.052, hierarchical 95% interval -0.006 to +0.127, decision C - and BEFORE any additional seed was trained)
* The PRIMARY analysis and its decision stay as pre-registered: seeds 0-4, decision C (inconclusive). They will not be replaced.
* Because disk space recovered (3.3 GB free) and the brief prefers ten seeds, seeds 5-9 of the same primary recipe are trained as a **sensitivity analysis**. Whatever they show - including a verdict that would change from C - is reported next to the primary result and labelled as secondary; extending the number of seeds after seeing an inconclusive result is a form of optional stopping and is therefore not allowed to change the primary verdict.
* The ten-seed analysis uses exactly the same procedure (hierarchical bootstrap, B = 10,000, same decision categories) and is saved as `outputs/stats/primary256_seeds0to9_stats.json`.
* Only an enlarged, frozen, template-disjoint test set (Section 4.5.10 of the report) can settle the question: more seeds reduce training-seed uncertainty but cannot reduce test-set uncertainty.

## Addendum 2 - unseen / synthetic challenge set (written after images were generated and while OCR was running; BEFORE any model was scored on it)
**Why:** the real test set (386 documents) is too small to settle Q1. A search found no further labelled real documents for the 16 classes: every public source on disk is already in the project manifest, and a web search found no open dataset with expense-category labels for utilities/rent/fuel/parking (candidates found cover only restaurant/shop receipts and would need labelling by the study author, i.e. not independent). So a synthetic challenge set was built instead.
**What it is:** `unseen_synthetic/` - 576 documents, 16 classes x 3 conditions (clean, noisy photo, long preamble) x 12, generated by `gen_unseen.py` (seed 20261101), a generator independent from the project's `scripts/generate_synthetic_data.py`: new merchants, item vocabulary, titles, field labels, four new layouts, boilerplate that carries no label information. Group = class|merchant|layout (250 groups). OCR: RapidOCR (CPU), `ocr.jsonl`. No document is removed after seeing results; OCR failures are counted and reported.
**What it can and cannot show:** labels are correct by construction but the documents were written by the same author as the label definitions and the generator style resembles the project's synthetic training data in spirit, so this measures robustness to wording / layout / noise / length shift, NOT real-world accuracy. A result here is never pooled with the real test set and never replaces the primary decision. The 'long' condition is intentionally constructed so the informative lines come after ~250+ tokens of boilerplate; it is a truncation stress test, and a XLM-R-256 deficit there is expected by construction, not evidence about real documents (in the real test set 47.4% of documents exceed 256 tokens).
**Frozen models:** TF-IDF refit artifact (`outputs/tfidf/tfidf_lr_refit.joblib`), XLM-R `primary256` seeds 0-4 (primary) and 5-9 (if completed; sensitivity). Nothing is retrained, re-calibrated, thresholded or selected on this set.
**Analysis (fixed now):** macro-F1 over the 16 classes (all present), accuracy, per-class F1; hierarchical bootstrap B = 10,000 over groups and seeds (same code path as the primary analysis); per condition and pooled-equal-weight over the three conditions; decision categories A-D with the same 0.02 threshold, reported as "synthetic-challenge verdict". Also the TF-IDF with the same 256-token truncation applied (to separate truncation from model family). No hyper-parameter changes after seeing results; whatever the outcome (XLM-R better, worse or equal) is reported.
**Decision value:** if XLM-R's advantage persists on this set it supports (does not prove) that the real-test gain is not a quirk of 386 documents; if it disappears or reverses it supports that the real gain is fragile. Either way the primary verdict (C) is unchanged unless a new REAL labelled set is evaluated.

## Addendum 3 - downloaded REAL unseen documents (written after the labels were built from company names and BEFORE OCR or any model scoring of them)
**Source (downloaded with the user's explicit permission):** Zenodo record 6371710, Cruz & Castelli, "Dataset of invoices and receipts including annotation of relevant fields", CC BY 4.0, `1_Images.zip` (410,222,137 bytes, 813 Portuguese invoice/receipt photos) + `2_Annotations_Json.zip` (290 kB). It is the same dataset from which the project already uses a 109-image subset.
**Selection (`unseen_real/build_real_set.py`, rules fixed before scoring):** excluded the images already used by the project; excluded every image whose company appears among the project's selected companies (merchant/template disjointness); excluded blank-company images and companies matched by no rule (not guessed). Labels = merchant type by keyword rules on the dataset's own company field. Result: 336 documents / 70 companies: miscellaneous 267 (grocery, electronics, hardware), food 61, train 4, transport 3, parking 1.
**Limitations stated in advance:** (i) labels are silver (rule-derived by the study author, not independent human annotation); (ii) Portuguese-language documents, whereas the models were trained mainly on English/Indian documents - this is a domain-shift test, partly of the OCR + multilingual ability, which is exactly where XLM-R might help, but also where the TF-IDF character n-grams are language-agnostic; (iii) only two classes (miscellaneous, food) have >= 10 documents; fuel, hotel, medical, utilities, rent and all other classes are absent (fuel is absent only because the fuel companies GALP and BP are also in the project's training subset). A 16-class macro-F1 therefore cannot be computed.
**Analysis (fixed now):** primary = accuracy and macro-F1 over the two classes with >= 10 documents (misc, food), computed over ALL documents of those two classes with predictions among all 16 labels (errors into other classes count); same hierarchical/group bootstrap (groups = company, B = 10,000, seeds resampled), same A-D rule applied to the macro-F1 difference ("real-Portuguese verdict"); the 8 documents of the other classes are listed descriptively only. Frozen models as in Addendum 2; no tuning. Not pooled with the main real test set or the synthetic set.

## Addendum 4 - hybrid cascade "TF-IDF first, XLM-R for uncertain documents" (written BEFORE any hybrid prediction was computed or scored)
**System:** TF-IDF + LR (refit artifact) predicts every document. If its top-class probability >= tau the TF-IDF label is final; otherwise the document is sent to XLM-R (argmax of its logits). One hybrid per XLM-R seed (each seed has its own tau); nothing is retrained.
**tau selection (validation only):** grid tau in {0.30, 0.35, ..., 0.95, 1.00 (= always XLM-R)} plus "never route" (tau = 0). For each seed, tau = the value that maximises the validation REAL-ONLY macro-F1 of the hybrid; ties go to the larger tau (fewer XLM-R calls). Test/unseen data are never used to choose tau. The TF-IDF probabilities are the raw (uncalibrated) refit probabilities.
**Evaluation (fixed now):** (1) main real test set (n = 386): hybrid macro-F1 vs TF-IDF and vs XLM-R, hierarchical bootstrap B = 10,000 (groups and seeds resampled), the same A-D rule against TF-IDF; share of documents routed to XLM-R; (2) the two unseen sets at the validation-chosen tau (synthetic: pooled and per condition; real Portuguese: the two-class measure), same bootstrap; (3) descriptive only, not used for any decision: the test macro-F1 as a function of tau (routing curve). Seeds 0-4 are the primary hybrid analysis; seeds 0-9 are reported as secondary.
**Cost model:** expected per-document latency = TF-IDF latency + routed share x XLM-R latency (measured medians from `outputs/cost_analysis.json`; CPU end-to-end batch 1 and GPU), an estimate that assumes XLM-R runs only on routed documents and ignores queueing; it is labelled as an estimate. Worst case (everything routed) equals the sum of both.
**Interpretation limits:** the hybrid is judged on whether it keeps XLM-R's gain at lower cost; it is not a new model selected on test data. The main test set remains too small to settle the underlying question, so an inconclusive hybrid-vs-TF-IDF result is possible and will be reported as such.
