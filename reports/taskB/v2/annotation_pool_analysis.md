# Task B v2 - annotation pool analysis (`in_grocery_gst`, 169 photos)
Generated by `scripts/taskB/v2_prepare_pool.py`, `v2_orient_final.py`, `v2_pool_analysis.py`, `v2_candidates.py`. Everything here is OCR + deterministic regex. No Task B model output is used and **nothing in this report is ground truth**; counts of "contains X" are keyword/regex detections on OCR text and under-count true presence where OCR is poor.

## 1. Preparation (Phases 1)
- Originals untouched (`datasets/public/indian_grocery_gst/Photos/Photos/`). Working copies: `datasets/interim/v2_pool/images/<id>.jpg` (EXIF-corrected, rotated upright, long side <= 3000 px, 245 MB incl. OCR). OCR (RapidOCR-ONNX on the GPU, words + boxes + per-word confidence): `datasets/interim/v2_pool/ocr/<id>.json`. Orientation evidence per page: `orientation.json`.
- Orientation was the hard part: phone photos are rotated 0/90/180/270 (final: 0: 56, 90: 58, 180: 15, 270: 40). The first two probe methods (OCR confidence, invoice-vocabulary score) were fooled because RapidOCR's angle classifier flips upside-down lines before recognition, and at 1800 px the tiny text was unreadable. Final method: text-line geometry decides horizontal vs vertical text, then recognition WITHOUT the angle classifier picks between the two candidates. I checked 20 pages visually (7 previously-wrong + 13 random): all upright. Not every one of the 169 was inspected; residual orientation errors are possible.
- OCR quality: median 189 words/page, mean word confidence >= 0.85 on 166/169 pages; 140/169 meet my "readable" bar (>= 100 words and mean conf >= 0.88).

## 5. Candidates + review tool (Phases 4-7)
- `datasets/interim/v2_pool/review_candidates.json` and `review/review_candidates.csv`: per page - original image, orientation, OCR text, OCR boxes, supplier/GSTIN/invoice no/date/subtotal/CGST/SGST/IGST/HSN/total candidates with boxes, every candidate `status = SUGGESTION_ONLY`. GSTIN suggestions list seller-looking GSTINs before the buyer's.
- Review tool: `python scripts/taskB/v2_review_tool.py` regenerates `datasets/interim/v2_pool/review/index.html` (static file, no server needed except to load images - from `datasets/interim/v2_pool/` run `python3 -m http.server 8765` and open `http://127.0.0.1:8765/review/index.html`). Shows the corrected page with OCR boxes; per field: accept a suggestion, edit text, set null, draw/re-draw a box (auto-fills text from OCR words inside it), mark page unusable, verified-against-image checkbox, annotator, notes; progress in browser localStorage; **Export annotations.json** with value, bbox, status, source, document_id, annotation_status, annotator, original_suggestion, final_value, verified_against_image and whether the human agrees with the top suggestion. Tested in a browser (accept, null, box-draw, export fields) - no JS errors.
- No model predictions are displayed or used. No suggestion becomes a label until a human exports it.

## 6. Limits that matter for the decision
1. One buyer, one city (West Bengal), Sept-Oct 2025 distributor invoices: strong for CGST/SGST/GSTIN/HSN/multi-rate, weak for merchant diversity and nearly absent for IGST (4 pages).
2. Retail/B2B distributor invoices with 30+ line items per page, dense tiny print, 34 multi-page documents: field boxes (esp. HSN, which repeats per line) need a convention (first HSN? the total tax lines?). Decide before annotating: this report assumes `hsn_sac` = the first HSN in the line table, `cgst/sgst` = the invoice total of that tax, `subtotal` = amount before tax.
3. Seller names are often glued/garbled by OCR; supplier grouping uses name regexes + GSTIN/PAN and is approximate.
4. Rights: pool is CC-BY-4.0 (attribution required; confirm the original dataset citation). Pages show a private shop's name/phone and a handwritten signature: keep the derived annotations out of any public release.
5. The frozen V1 test set cannot receive these pages. They can add training/validation/CV evidence only; on the frozen test, GSTIN/CGST/SGST stay INSUFFICIENT REAL TEST SUPPORT.
